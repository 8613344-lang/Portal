# Индексация и поисковые фразы

## Что добавлено

Главная, публичный каталог, страница заказа и страница `/personalnaya-kniga/` имеют собственные заголовки и описания. У опубликованных публичных книг есть страницы `/stories/<slug>/`: название, описание, обложка, небольшой фрагмент и переход к чтению. Название и описание редактируются через существующие поля книги в админке.

Добавлены canonical, Open Graph, карточки ссылок и JSON-LD WebSite / Organization / Service / Book / BreadcrumbList. Разметка не содержит вымышленных цен, оценок, адресов или отзывов. Текст, ссылки, метаданные и карта сайта выдаются сервером; JavaScript не требуется для обнаружения страниц. Основной просмотрщик, Android, PDF и режимы доступа сохраняют прежнее поведение.

## Карта сайта и приватность

- `/robots.txt` разрешает обход и указывает на `/sitemap.xml`.
- `/sitemap.xml` перечисляет `/sitemap-pages.xml` и `/sitemap-books-N.xml`.
- Публичные книги разбиты на файлы по 1000 URL; каталог имеет собственные канонические адреса страниц пагинации.
- Карты обновляются из базы при запросе. Публичная страница книги доступна только при `status=published` и `visibility=public`. Черновики, архивные и закрытые книги исключены даже для сотрудников и обладателей прямой ссылки.
- Закрытые страницы, кабинеты, регистрация, приложение/полка, поиск по каталогу, просмотрщики, QR-ссылки, видео, выгрузки и исходные медиа получают `X-Robots-Tag: noindex`; HTML дополнительно получает соответствующий meta robots.
- Прямые ссылки с секретными идентификаторами никогда не добавляются в карту сайта или поисковую разметку. Книга остаётся защищена проверкой прав; noindex дополняет её, а не заменяет.

Robots.txt не блокирует получение страниц с noindex: робот должен прочитать запрет индексации. [Объяснение Google](https://developers.google.com/search/docs/crawling-indexing/block-indexing). Публикация книги означает разрешение индексировать её публичное описание; для персональных историй используйте закрытый доступ. Отзыв публикации сразу закрывает `/stories/<slug>/` ответом 404 и убирает URL из карты; поисковые системы обновят свою базу после повторного обхода.

## Обновление qicko.ru

В серверном `.env` проверьте основной адрес:

```dotenv
SITE_URL=https://qicko.ru
DOMAIN=qicko.ru
ALLOWED_HOSTS=qicko.ru,localhost,127.0.0.1
CSRF_TRUSTED_ORIGINS=https://qicko.ru
```

Сохраните дополнительные имена хостов, если они нужны вашей установке. Метаданные и sitemap используют SITE_URL, а не присланный клиентом Host. Для разработки можно оставить адрес локального сервера.

```bash
git pull --ff-only
docker compose up -d --build
```

Новых миграций для SEO нет. Статика собирается стандартным запуском контейнера. Android 1.5 менять не требуется. При запуске без Docker обновите код, выполните `python manage.py collectstatic --noinput` и перезапустите веб-процесс.

После обновления проверьте:

```bash
curl -I https://qicko.ru/
curl https://qicko.ru/robots.txt
curl https://qicko.ru/sitemap.xml
curl https://qicko.ru/sitemap-pages.xml
```

Главная должна отвечать 200 и `X-Robots-Tag: index, follow`; в её исходнике canonical должен указывать на `https://qicko.ru/`. Карты должны содержать адреса qicko.ru, без localhost. Кабинет и закрытые/служебные страницы должны оставаться noindex. Публичные обложки остаются доступны для показа на сайте; исходные файлы не предназначены для отдельного поиска по картинкам.

## Яндекс Вебмастер

1. Откройте [Яндекс Вебмастер](https://webmaster.yandex.ru/) и выберите сайт `https://qicko.ru/`.
2. Если владение ещё не подтверждено, используйте уже установленный файл `/yandex_09163709ffc9d3bb.html` и нажмите проверку.
3. В разделе «Индексирование → Файлы Sitemap» добавьте `https://qicko.ru/sitemap.xml`.
4. Проверьте карту инструментом анализа Sitemap и отправьте главную и `/personalnaya-kniga/` на переобход.
5. Отслеживайте ошибки обхода и страницы в поиске. Карту не нужно пересоздавать вручную при добавлении книг.

Источник: [инструкция Яндекса по Sitemap](https://www.yandex.ru/support/webmaster/ru/indexing-options/sitemap).

## Google Search Console

1. Откройте [Google Search Console](https://search.google.com/search-console/) под аккаунтом владельца.
2. Добавьте ресурс с префиксом `https://qicko.ru/` и выберите подтверждение HTML-тегом (либо подтвердите домен через DNS).
3. Для HTML-тега скопируйте **только значение content** в серверный `.env`:

```dotenv
GOOGLE_SITE_VERIFICATION=значение_из_Google_Search_Console
```

4. Выполните `docker compose up -d --build`, проверьте появление meta google-site-verification в исходнике главной и нажмите подтверждение в Google. Сохраните значение в .env после проверки.
5. В разделе Sitemaps укажите `sitemap.xml`. Через проверку URL отправьте главную и страницу услуги на индексирование.

Источник: [отправка карты Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

Авторизация в Яндекс Вебмастере и Search Console выполняется владельцем. В этой доработке карты подготовлены для обнаружения роботами, но отправка из личных аккаунтов не выполнялась. Добавление sitemap не гарантирует индексацию каждой страницы или конкретные позиции в выдаче. Проверяйте реальные запросы и показы в кабинетах, постепенно улучшайте описания публичных книг и добавляйте полезные примеры. [Как Google использует описания страниц](https://developers.google.com/search/docs/appearance/snippet).
