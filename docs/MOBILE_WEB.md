# Мобильный сайт и ярлык на главном экране

Сайт адаптируется к телефону и планшету по ширине экрана. На небольших экранах и планшетах с сенсорным вводом появляется нижняя навигация: «Главная», «Мои книги», «Создать», «Войти» / «Профиль». Учтены безопасные отступы экрана; поля форм используют шрифт 16 px. В режиме «Начать просмотр» нижняя навигация и предложение установки скрываются, остаются элементы управления книгой.

## Предложение установки

В мобильном браузере появляется компактная карточка «Ваши книги — под рукой». «Как добавить» открывает `/install/` с инструкцией для устройства. Инструкции для iPhone/iPad и Android можно переключать вручную; обе доступны и при отключённом JavaScript. Ссылка «Добавить на экран» всегда есть в подвале сайта, в том числе на компьютере.

Если браузер отправляет `beforeinstallprompt`, карточка меняется на «Установить», а на странице инструкции появляется «Добавить на экран»: нажатие открывает системный диалог. Браузер сам решает, доступна ли установка; если кнопки нет или установка отменена, используйте меню по инструкции. Установка всегда требует действия пользователя.

Крестик скрывает предложение на семь дней в этом браузере. После подтверждения установки оно скрывается на 90 дней. Срок хранится в localStorage; при блокировке хранилища сайт и инструкции продолжают работать, но срок скрытия между открытиями не сохраняется. При запуске уже добавленного сайта как отдельного приложения предложение скрыто. В нативных экранах Android-приложения оно не добавляется.

## iPhone и iPad

1. Откройте сайт в **Safari**. Если открыли ссылку внутри Telegram или почты, используйте «Открыть в Safari».
2. Нажмите **«Поделиться»** — квадрат со стрелкой вверх на панели Safari.
3. Выберите **«На экран Домой»**. При необходимости прокрутите список или проверьте «Изменить действия».
4. Если доступен переключатель **«Открывать как веб-приложение»**, включите его. Нажмите **«Добавить»**.

Положение кнопок и переводы пунктов зависят от версии системы. Ярлык нужно добавить отдельно на каждом устройстве. [Инструкция Apple](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios).

## Android: телефон и планшет

1. Откройте сайт в браузере, например Chrome.
2. Если на `/install/` появилась кнопка «Добавить на экран», нажмите её и подтвердите действие в диалоге браузера.
3. Если кнопки нет, откройте меню **⋮** → **«Установить приложение»** или **«Добавить на главный экран»**, затем подтвердите добавление. Название зависит от браузера.

В некоторых браузерах создаётся обычный ярлык, в других — веб-приложение с отдельным окном. [Варианты установки](https://web.dev/learn/pwa/installation), [условия установки и beforeinstallprompt](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Что открывает ярлык

Manifest `/manifest.webmanifest` задаёт название «Книги рядом», собственные иконки 192/512 px, maskable-иконку, русский язык, отдельное окно (`standalone`) и начальный адрес **`/shelf/`**. Сначала показываются персональные книги вошедшего пользователя, затем публичные. Если в новом окне нет входа в аккаунт, войдите заново. Права книг, PDF и видео проверяет сервер; установка не меняет их.

Для Safari добавлена apple-touch-icon 180×180. Иконки подготовлены из существующей иконки приложения. Android APK пересобирать не требуется.

## Интернет и приватность

Ярлык открывает онлайн-версию. Книги автоматически не скачиваются. Для чтения без сети заранее сохраните PDF; нативное Android-приложение также имеет свой ранее реализованный режим сохранённых книг.

Service worker **`/service-worker.js`**, область `/`, кэширует **только общую страницу `/offline/`**, без данных аккаунта. Навигация всегда идёт в сеть; при сетевой ошибке возвращается эта страница с предложением подключиться и повторить открытие полки. HTTP-ошибки доступа (например, 403/404) возвращаются без подмены. Страницы книг, приватные файлы, фотографии заказов, ответы API, формы и POST-запросы не записываются в Cache Storage. Обычный браузерный HTTP-кэш по-прежнему соблюдает серверные заголовки.

Рабочий сайт должен открываться по **HTTPS**, например `https://qicko.ru/`. Для разработки подходит `http://127.0.0.1:8000`. Адрес вида `http://192.168.x.x:8000` на телефоне не обеспечивает secure context для service worker; ручное добавление ярлыка может зависеть от браузера.

## Обновление сервера

~~~bash
git pull --ff-only
docker compose up -d --build
~~~

При обычном запуске Python перезапустите процесс сайта после сбора статики:

~~~powershell
.venv/Scripts/python.exe manage.py collectstatic --noinput
.venv/Scripts/python.exe -m waitress --listen=127.0.0.1:8000 portal.wsgi:application
~~~

Новых миграций нет. Прокси должен передавать `/manifest.webmanifest`, `/service-worker.js`, `/offline/`, `/install/` в Django. Стандартная конфигурация проекта это делает. Manifest и worker не имеют длительного HTTP-кэша; worker обновляется браузером автоматически. При изменении самой офлайн-страницы увеличьте версию `qicko-offline-v1` в шаблоне worker: старый кэш этого сайта очистится при активации новой версии.

## Проверка перед публикацией

Откройте HTTPS-сайт в реальных Safari на iPhone/iPad и браузере Android. Проверьте добавление ярлыка, правильную иконку, запуск книжной полки, вход, просмотр книги и переключение ориентации. В инструментах браузера проверьте Manifest, активный Service Worker и Cache Storage: единственная сохранённая страница — `/offline/`. Отключите сеть, откройте полку, затем подключитесь и нажмите «Попробовать снова».

Серверные тесты и Edge с эмуляцией размеров/признаков устройств не заменяют проверку системного диалога и установленного ярлыка на физических iOS/Android.
