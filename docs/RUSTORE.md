# Qicko: сборка APK и публикация в RuStore

Версия **1.4, versionCode 5**, пакет **ru.portal.books**. Один APK для телефона и планшета, Android 8.0+. Сервер https://qicko.ru/ задан в приложении. Первая публикация: создан постоянный ключ, APK подписан им. В магазин приложение автоматически не отправлялось.

## 1. Файлы комплекта

| Файл | Назначение |
| --- | --- |
| [PortalBooks-1.4-rustore.apk](../android/releases/PortalBooks-1.4-rustore.apk) | **Загрузить в RuStore Консоль** |
| [qicko-rustore-kit-1.4.zip](../rustore/qicko-rustore-kit-1.4.zip) | APK, исходники Android, инструкции, материалы карточки |
| PortalBooks-1.4-rustore.apk.sha256 | Контрольная сумма |
| PortalBooks-1.4-rustore-certificate.txt | Отпечаток сертификата и проверка release |
| rustore/listing.json | Тексты карточки, поля владельца для заполнения |
| rustore/icon-512.png | Иконка 512×512 |
| rustore/phone/ и rustore/tablet/ | По три скриншота |
| [MODERATION.md](../rustore/MODERATION.md) | Сценарий проверки и комментарий модератору |

В консоль загружается APK, а не ZIP и не сертификат. Ключ и пароль исключены из публичного архива и Git.

## 2. Сохраните ключ

На этом компьютере ключ: **Portal/.private/android-signing/qicko-release.jks**, alias **qicko**. Пароль хранится в password.clixml, зашифрованном Windows DPAPI для создавшего его пользователя этого компьютера.

Для обновлений нужен этот же ключ. Не создавайте другой вместо него. Сделайте личные резервные копии JKS и пароля; один CLIXML не является переносимой копией пароля. Извлечение пароля и перенос подробно описаны в [SIGNING.md](SIGNING.md).

## 3. Инструменты Windows

1. Установите [Android Studio](https://developer.android.com/studio).
2. Откройте **Portal/android** через Open — папку с settings.gradle.
3. В SDK Manager установите Android SDK Platform 35, Build-Tools 35.0.0 и Platform-Tools.
4. В настройках Gradle выберите JDK 17 или совместимую встроенную JDK Android Studio.
5. Дождитесь Gradle Sync. Первая сборка требует интернет.

В проекте уже есть AGP 8.9.1 и Gradle Wrapper 8.11.1; отдельно Gradle не устанавливается. Из распакованного комплекта открывается его папка android. Сервер Django в APK не входит.

## 4. Сборка PowerShell-скриптом

На компьютере, где создан ключ, откройте PowerShell в папке Portal:

~~~powershell
.\android\build-rustore.ps1
~~~

Скрипт читает локальный зашифрованный пароль, собирает release, выполняет lint и проверяет подпись, пакет, версию, MAIN/LAUNCHER и отсутствие отладки. Результат в android/releases:

~~~text
PortalBooks-1.4-rustore.apk
PortalBooks-1.4-rustore.apk.sha256
PortalBooks-1.4-rustore-certificate.txt
~~~

Если JDK/SDK установлены по другим путям:

~~~powershell
.\android\build-rustore.ps1 -JavaHome 'C:/Program Files/Android/Android Studio/jbr' -SdkPath "$env:LOCALAPPDATA/Android/Sdk"
~~~

Если ключ восстановлен на другом компьютере:

~~~powershell
.\android\build-rustore.ps1 -KeystorePath 'D:/SecureKeys/qicko-release.jks' -KeyAlias 'qicko'
~~~

Последний вариант запросит пароли хранилища и ключа скрытым вводом; у созданного ключа они совпадают. Пароли не записываются в командную строку и не сохраняются скриптом. После сборки окружение восстанавливается.

Флаг -Offline подходит только при уже загруженных зависимостях. При ошибке Maven/Gradle проверьте интернет; офлайн-режим не скачивает недостающие файлы.

## 5. Альтернатива: Android Studio

1. Откройте Portal/android и дождитесь синхронизации.
2. Build → Generate Signed App Bundle or APK → APK.
3. Модуль app; Key store path — существующий qicko-release.jks; alias — qicko. Введите пароли.
4. Выберите release и завершите сборку.
5. Locate откроет результат. Обычно это app/build/outputs/apk/release/app-release.apk; место, выбранное в мастере, может отличаться.
6. Проверьте файл SDK:

~~~powershell
& "$env:LOCALAPPDATA/Android/Sdk/build-tools/35.0.0/apksigner.bat" verify --verbose --print-certs 'ПОЛНЫЙ/ПУТЬ/К/app-release.apk'
~~~

SHA-256 сертификата должен совпадать с отчётом комплекта; сертификат не Android Debug. Готовый скрипт дополнительно проверяет APK и даёт однозначное имя.

Справки: [подпись Android](https://developer.android.com/studio/publish/app-signing), [apksigner](https://developer.android.com/tools/apksigner).

## 6. Обновите сервер и проверьте

Сайт этой версии содержит метаданные офлайн-полки, документ внутри приложения и удаление аккаунта. Перед публикацией:

~~~bash
git pull --ff-only
docker compose up -d --build
~~~

На сервере нужны SITE_URL=https://qicko.ru, подходящие ALLOWED_HOSTS и CSRF_TRUSTED_ORIGINS, действующие HTTPS и SMTP. Почта: [ACCOUNTS.md](ACCOUNTS.md).

Установите release на телефон и планшет. Старый debug подписан другим ключом: при конфликте удалите тестовую версию и установите release заново. Это сбрасывает локальные загрузки и вход, но не серверные книги.

Проверьте:

1. Публичные книги открываются без входа и запроса сайта.
2. Вход по email показывает персональные книги выше публичных.
3. Работают просмотр, листание, аудио, пауза, поворот и возврат.
4. «Сохранить PDF» сохраняет книгу; «Без интернета» открывает её без сети. PDF-копия не содержит озвучку.
5. Работают удаление загрузки, запоминание страницы и очистка персональных копий при выходе.
6. Открываются политика и удаление обычного аккаунта с паролем/подтверждением. Для проверки удаления используйте ненужный тестовый аккаунт.
7. Подтверждение email и восстановление действительно приходят на почту. Локальные тесты SMTP-доставку не подтверждают.

Скриншоты демонстрируют тестовые книги без реальных данных детей. Сравните их с актуальным интерфейсом рабочего сервера.

## 7. Сведения владельца

Владелец пока не определился с публичным именем разработчика и email поддержки. Поля отмечены в listing.json и отчёте архива; перед отправкой замените их реальными данными.

Выберите категорию и возраст по содержимому каталога, завершите конфиденциальность на /privacy/, проверьте права на иллюстрации, тексты и аудио.

Для анкеты данных: используются email, отображаемое имя, сессия и назначенные книги; истории могут содержать сведения ребёнка. По выбору пользователя на устройстве хранятся PDF и позиция чтения. Разрешение — INTERNET; рекламных/аналитических SDK нет. Учитывайте фактическую обработку сервером.

## 8. Регистрация разработчика

1. Откройте [RuStore Консоль](https://console.rustore.ru/) и войдите через VK ID.
2. Выберите фактический тип: физлицо, ИП или организация.
3. Заполните профиль и выполните проверку консоли. Для разных типов и стран процедуры отличаются.

Сверяйтесь с [официальной регистрацией](https://www.rustore.ru/help/developers/developer-account/registration-developer); выдуманные реквизиты в комплект не подставлены.

## 9. Загрузка и карточка

1. Добавьте приложение, загрузите PortalBooks-1.4-rustore.apk.
2. Проверьте пакет ru.portal.books, версию 1.4, код 5.
3. Перенесите тексты из listing.json, заполните оставшиеся поля.
4. Загрузите icon-512.png, три снимка phone и три tablet.
5. Укажите поддержку, политику, категорию, возраст, сведения о данных; заявляйте телефон и планшет.

Лимиты: имя до 30 символов, короткое описание до 80, полное до 4000. Иконка 512×512 до 3 МБ; минимум три снимка каждого заявленного типа, до 3 МБ для телефона и 5 МБ для планшета. Сверьте поля с [инструкцией RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication).

## 10. Модерация и выход

Создайте на рабочем сервере отдельный обычный аккаунт проверяющего, подтвердите email, выдайте демонстрационную книгу. Доступ передайте в закрытом комментарии версии, не в описании/Git/ZIP. Шаблон — rustore/MODERATION.md.

Выберите ручную публикацию для самостоятельного запуска после проверки. Отправьте версию на модерацию, исправьте замечания. После готовности нажмите «Опубликовать», проверьте установку из магазина. [Ручная публикация](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/setting-up-publication/instant-app-publishing).

Нативный офлайн-просмотр, политика и удаление аккаунта адресуют требования к WebView и аккаунтам из [правил модерации](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps). Одобрение зависит также от содержимого и рабочего сервера.

## 11. Обновления

1. Сохраните applicationId и этот же ключ.
2. Увеличьте versionCode в android/app/build.gradle; обновите versionName и listing.json.
3. Выполните build-rustore.ps1 и проверьте установку поверх предыдущего release.
4. Обновите материалы и упакуйте:

~~~powershell
.venv/Scripts/python.exe tools/package_rustore.py
~~~

5. Загрузите APK как версию существующего приложения. Код должен быть выше всех использованных выпусков, включая тестовые каналы. [Версии Android](https://developer.android.com/studio/publish/versioning).
