# Публикация Qicko в RuStore

Подготовлены исходники Android 1.3 (`versionCode=4`), подписанный APK для личной проверки, тексты карточки, иконка и скриншоты. Для публикации release необходимо собрать с постоянным ключом владельца. Приложение всегда открывает `https://qicko.ru/app/`; настройки адреса нет. Пакет — `ru.portal.books`, Android 8.0+, телефон и планшет. Онлайн-просмотрщик работает с вашим сервером. Это подготовка материалов, приложение в магазин не отправлялось.

Актуальный комплект: [qicko-rustore-kit-1.3.zip](../rustore/qicko-rustore-kit-1.3.zip). Архивы 1.1/1.2 относятся к предыдущим версиям; для установки используйте текущий `PortalBooks-1.3-install.apk`.

## Что находится в репозитории

- `rustore/listing.json` — название, короткое/полное описание, изменения версии и поля карточки.
- `rustore/icon-512.png` — иконка 512×512 с непрозрачным фоном.
- `rustore/phone/` — три PNG 720×1280: каталог, чтение, вход.
- `rustore/tablet/` — три PNG 1920×1080 для планшета.
- `android/releases/PortalBooks-1.3-install.apk` — подписанный тестовым ключом APK для личной проверки. **Не используйте его для публикации.**
- `android/releases/SHA256SUMS-1.3.txt` — контрольная сумма установочного файла.
- `rustore/privacy-draft.md` — заготовка сведений о данных; требует заполнения владельцем.

Скриншоты сняты с общего интерфейса WebView на тестовом аккаунте и демонстрационных книгах, без реальных данных читателей. Перед публикацией полезно заменить их снимками физического устройства, особенно если системная оболочка меняет отображение. Служебный тестовый аккаунт удаляется после съёмки и не подходит для модерации.

## 1. Сначала обновите платформу

```bash
git pull
docker compose up -d --build
```

Для qicko.ru проверьте `SITE_URL=https://qicko.ru`, домены в `ALLOWED_HOSTS` и HTTPS-адреса в `CSRF_TRUSTED_ORIGINS`. Настройте действующий SMTP и адрес отправителя в `.env` по `docs/ACCOUNTS.md`. Подтвердите, что пользователь получает письмо с кодом и письмо восстановления на настоящую почту. Проверки с тестовой почтой в Django не подтверждают работоспособность вашего SMTP.

Откройте `/accounts/register/`, создайте обычный аккаунт, подтвердите email, выдайте ему персональную опубликованную книгу через админку. Проверьте вход, чужой закрытый URL, отзыв доступа, изменение имени в профиле, восстановление пароля, выход. В приложении проверьте поворот, переходы, озвучку, паузу при сворачивании, возврат в каталог и работу на телефоне/планшете. Полное физическое тестирование пока не выполнялось.

## 2. Заполните сведения владельца

В `listing.json` отмечены незаполненные поля владельца и email поддержки. Не отправляйте карточку с этими заглушками. Определите, кто публикует приложение, какой контакт отвечает на обращения и кто является оператором данных qicko.ru. Добавьте реальные реквизиты, порядок обращений и сроки хранения в политику сайта. Сейчас `/privacy/` содержит заготовку с просьбой заполнить реквизиты; до магазина её нужно завершить. Проверьте права на иллюстрации и тексты.

Сведения для анкеты безопасности по реализации: приложение использует email, отображаемое имя и сессию аккаунта. Пароли обрабатывает сервер; подтверждение и восстановление используют email. Через приложение видны персональные книги, которые могут содержать данные ребёнка. Разрешение Android — только INTERNET; нет SDK рекламы, аналитики, геолокации, камеры, микрофона и встроенных платежей. Отдельная форма заказа на сайте обрабатывает дополнительные данные; учтите её в политике сайта, хотя в Android-каталоге она не отображается.

## 3. Подпишите release своим постоянным ключом

Для магазина нужен собственный ключ владельца. Тестовый debug-ключ не является ключом публикации. Если пакет уже публиковался, используйте прежний ключ. Если это первая публикация, откройте папку `android` в Android Studio → Build → Generate Signed App Bundle or APK → APK. Создайте keystore вне Git, задайте alias и пароли, выберите release. Сделайте защищённую резервную копию ключа и паролей: они нужны для следующих обновлений.

Альтернатива через Gradle — передать переменные окружения только на время сборки:

```powershell
$env:RUSTORE_KEYSTORE = 'C:/secure/qicko-release.jks'
$env:RUSTORE_KEY_ALIAS = 'qicko'
# Введите пароли через защищённый ввод/менеджер секретов, не сохраняйте их в Git.
# RUSTORE_STORE_PASSWORD — пароль хранилища
# RUSTORE_KEY_PASSWORD — пароль ключа
cd android
.\gradlew.bat assembleRelease lintRelease
```

Выход: `app/build/outputs/apk/release/app-release.apk` при заданной конфигурации подписи. Без полного набора переменных или подписи Android Studio сборка останавливается с ошибкой; неподписанный release не является готовым установочным файлом. После сборки удалите секреты из окружения. SDK `apksigner verify --verbose <файл.apk>` должен подтвердить подпись. Установите именно подписанный release на чистое устройство. Проверьте отсутствие запроса адреса, подключение к qicko.ru и все шаги пользователя. Удалите debug-версию перед установкой, если её подпись отличается. Не меняйте package name после первой публикации. Следующий выпуск должен увеличивать `versionCode` и сохранять ключ.

## 4. Создайте карточку в консоли

Актуальные требования проверены 14 октября 2026 по [официальной инструкции RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication): новый проект добавляет владелец компании; APK должен быть подписан. Название ограничено 30 символами, краткое описание — 80, полное — 4000. Иконка 512×512, до 3 МБ, PNG/JPG. Для каждого типа устройств требуется минимум три скриншота; лимиты файла — 3 МБ для телефона, 5 МБ для планшета. У последующих версий должны сохраняться пакет и подпись, а код версии увеличиваться.

1. Войдите в [RuStore Консоль](https://console.rustore.ru/), завершите оформление профиля владельца и подтверждение его сведений.
2. В разделе приложений создайте карточку, затем загрузите подписанный release-APK. Дождитесь результата проверки файла.
3. Перенесите тексты из `listing.json`. Выберите категорию чтения из предлагаемого списка и заполните возрастную анкету по содержимому книг. Проверьте уникальность названия в консоли; предложенное название может потребовать корректировки.
4. Укажите действующие контакты поддержки, сайт qicko.ru и завершённую политику. Заполните сведения о данных согласно вашей фактической работе сервера.
5. Загрузите иконку, три изображения телефона и три планшета. Не заявляйте TV-версию: в этом проекте она не реализована.
6. Для модерации подготовьте отдельный обычный аккаунт на qicko.ru, подтвердите его email, назначьте демонстрационную персональную книгу. Передайте логин-email и пароль через закрытое поле консоли для проверяющих, **не в общедоступное описание и не в Git**. Аккаунт не должен быть администратором или содержать реальные данные ребёнка.
7. Просмотрите карточку, загрузку и демонстрационный сценарий, выберите способ выхода версии и отправьте на модерацию. Если есть замечания, исправьте указанный пункт и повторите отправку. Подготовка пакета не гарантирует решение модерации.
8. После одобрения проверьте установку из RuStore, вход и доступ к книгам. Для обновлений сохраняйте ключ, повышайте `versionCode`, добавляйте описание изменений и повторяйте проверки.

Ключи: [официальная инструкция по подписям](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/apk-signature). Финальную отправку выполняет владелец в своей консоли; доступ и ключ подписи в этой задаче не предоставлены.
