# Заявки, тарифы и воронка

## Обновление

После резервной копии базы обновите код и пересоберите действующие сервисы:

```bash
git pull --ff-only
docker compose up -d --build
docker compose exec app python manage.py setup_groups
```

Контейнер `app` применяет миграции при старте. Без Docker запустите `python manage.py migrate`, `python manage.py collectstatic --noinput`, `python manage.py setup_groups` и перезапустите сайт и процессы уведомлений и аналитики. Если права сотрудников назначены вручную, вместо обновления стандартных групп выдайте нужные разрешения через админку.

Миграция 0014 добавляет тарифы и три документа. Имеющиеся заявки сохраняются; старые этапы аналитики не восстанавливаются. В админке:

1. **Тарифы на книги** — проверьте цены и комплектацию. Значения одновременно обновляются на главной, в FAQ и в заявке. Доплаты за озвучку и печать вводятся отдельно. Если доплата не указана, при выборе опции её стоимость нужно согласовать. Отдельно согласуются доставка и твёрдый переплёт.
2. **Документы сайта** — вставьте окончательные тексты согласия, политики и оферты. Проверьте публичные страницы `/documents/consent/`, `/documents/policy/`, `/documents/offer/`. Тексты изначально пусты и публикуются при сохранении. Если согласие опубликовано, заявка сохраняет идентификатор его редакции; если текст изменился в процессе заполнения, пользователь подтверждает новую редакцию.
3. **Заказы** — проверьте, что менеджер видит выбранный тариф и цену на момент отправки заявки. Подписка оформляется как заявка на пакет книг; списаний через сайт и автопродления нет.
4. **Воронка заказов** — проверьте разрешение `view_orderfunnelevent` у сотрудников, которым доступна статистика.

## Что считается событием

| Событие | Когда фиксируется |
| --- | --- |
| Начало формы | При первом изменении поля или при первой попытке отправить шаг |
| Переход к контактам | Когда имя, возраст и повод прошли проверку |
| Ошибка заполнения | При невалидном шаге. Записываются только названия полей; можно увидеть число попыток и уникальных форм |
| Заявка отправлена | Когда заказ и очередь уведомлений сохранены |
| Заявка квалифицирована | Менеджер подтвердил, что контакт доступен и запрос подходит |
| Оплата подтверждена | Менеджер подтвердил фактическую оплату квалифицированного заказа |

Воронка считает события по дате их возникновения. Оплата за заявку прошлого периода может попасть в следующий период, поэтому деление оплат на заявки за один календарный период само по себе не показывает когортную конверсию. Журнал подчиняется `ANALYTICS_ENABLED` и `ANALYTICS_RETENTION_DAYS`; очистку выполняет `analytics_worker`. Содержимое полей и платёжные реквизиты не записываются в журнал. Отметки менеджера остаются в карточке заказа после очистки статистики.
