# Аккаунты: email, капча, подтверждение и восстановление

При регистрации вводятся имя, email, пароль, согласие и код с картинки. Имя может повторяться. Внутренний идентификатор Django создаётся автоматически; отображаемое имя хранится отдельно. Email нормализуется к нижнему регистру и защищён уникальным индексом БД. Вход на сайте и в Android выполняется по email; вход по старому username сохранён только для сотрудников через `/admin/`, чтобы не потерять доступ к управлению.

Новая учётная запись неактивна до подтверждения email. Код из шести цифр действует 10 минут; допускается пять неверных попыток. В БД хранится HMAC кода, не сам код. Повторное письмо — не чаще одного раза в минуту, с дополнительным ограничением запросов по IP. Капча действует пять минут и расходуется при попытке регистрации. Если страницу регистрации закрыли, используйте «Подтвердить email» на странице входа (`/accounts/confirm/start/`).

Профиль `/profile/` позволяет менять имя, показывает email и ведёт к смене пароля. Email здесь не меняется, чтобы не обойти подтверждение нового адреса. Восстановление `/accounts/password-reset/` отправляет одноразовую ссылку на почту активного аккаунта. Она действует час и становится недействительной после смены пароля. Ответ не сообщает, существует ли активный аккаунт с указанным адресом.

## Обновление

```bash
git pull
docker compose up -d --build
```

Применяются миграции `0006` и `0007`. Существующие активные аккаунты сохраняют доступ, книги и назначения. Прежде чем перейти на email, заполните email у пользователей, у которых он отсутствует. Если у нескольких аккаунтов один email без учёта регистра, миграция останавливается с сообщением: исправьте адреса через старую админку и повторите обновление. Аккаунты автоматически не объединяются и не удаляются. Сделайте резервную копию БД по основной инструкции развёртывания.

## Настройка писем

В `.env` задайте реквизиты реально работающего SMTP, используя значения своего провайдера:

```dotenv
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=SMTP_ВАШЕГО_ПРОВАЙДЕРА
EMAIL_PORT=587
EMAIL_HOST_USER=ВАШ_SMTP_ЛОГИН
EMAIL_HOST_PASSWORD=ВАШ_SMTP_ПАРОЛЬ
EMAIL_USE_TLS=1
EMAIL_USE_SSL=0
DEFAULT_FROM_EMAIL=ВАШ_ПОДТВЕРЖДЁННЫЙ_АДРЕС_ОТПРАВИТЕЛЯ
SITE_URL=https://qicko.ru
```

Для SSL-порта 465 используйте SSL=1, TLS=0. После изменения пересоздайте app и worker. Учётные реквизиты не коммитьте. Убедитесь, что SMTP-провайдер разрешает указанный адрес отправителя. Реальные письма в этой задаче не отправлялись: тесты используют локальный тестовый почтовый backend.

Отказ отправки подтверждения не активирует пользователя: на странице можно повторить отправку. Восстановление сохраняет нейтральный ответ и записывает тип ошибки отправки в журнал, поэтому при отсутствии письма проверьте SMTP и логи app. Коды, пароли и SMTP-секреты в журнал не записываются. Старые или неподтверждённые регистрации без письма можно продолжить через страницу подтверждения email.

После установки проверьте на собственной почте: регистрацию и получение кода, отказ входа до подтверждения, успешное подтверждение, вход по email в разном регистре, профиль, восстановление и вход с новым паролем. Не выставляйте тестовые почтовые backend в production.
