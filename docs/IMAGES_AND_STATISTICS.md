# Изображения, статистика и карточки главной

## Обновление сервера

```bash
git pull --ff-only
docker compose up -d --build
```

Миграция **0012_homepage_items_and_visits** добавляет карточки главной и журнал посещений. Стандартный запуск app применяет миграции и собирает статику. Сервис `analytics_worker` раз в час удаляет устаревшие записи статистики. Сайт и Android 1.5 получают изменения с сервера; новый APK не требуется.

Без Docker выполните миграции, collectstatic и перезапустите веб-процесс. Отдельно держите запущенным процесс очистки статистики:

```powershell
.venv/Scripts/python.exe manage.py migrate
.venv/Scripts/python.exe manage.py collectstatic --noinput
.venv/Scripts/python.exe manage.py run_analytics
```

Однократная очистка: `python manage.py run_analytics --once`. Настройки задаются в `.env`:

```dotenv
ANALYTICS_ENABLED=1
ANALYTICS_RETENTION_DAYS=90
ANALYTICS_TRUSTED_PROXIES=127.0.0.1/32,::1/128,172.16.0.0/12
```

`ANALYTICS_ENABLED=0` отключает сбор. Срок хранения можно изменить. Существующие записи старше срока удаляет worker. В обычной установке Docker Caddy перезаписывает X-Real-IP адресом клиента, backend доступен внутри сети. Приложение учитывает этот заголовок только при BEHIND_PROXY=1 и доверенном адресе подключившегося прокси. Для другой сети укажите её точный CIDR; произвольный X-Forwarded-For не используется.

## Облегчённые изображения

Обложки каталога, главной и полок, публичные страницы книг, иллюстрации и фоны просмотрщика используют `/web-image/<ширина>/<путь>`. Это WebP шириной до 320, 640, 960, 1280 или 1920 пикселей; маленькие оригиналы не увеличиваются, пропорции сохраняются. В HTML используются srcset/sizes, чтобы браузер выбрал подходящий вариант. Изображения вне экрана загружаются отложенно, где это уместно.

Копии создаются при первом запросе и хранятся в **приватном** `media/.web-images/`. Имя кэша зависит от источника, его размера, времени изменения и варианта изображения. Исходные файлы остаются на месте и используются в PDF/MP4: уменьшения оригиналов и необходимости пересоздавать видео из-за этой доработки нет.

Перед каждой выдачей и ответом 304 проверяются текущие права. Закрытая книга, отозванный доступ и отключённая обложка идеи не становятся публичными через кэш. Файлы нельзя раздавать напрямую из media; сохраняйте действующую проверку доступа через приложение. Ответы имеют private/no-cache и ETag, поэтому браузер может повторно использовать байты после проверки сервера.

Декоративные иллюстрации главной собраны в `static/images/web/`. Пример размеров: forest-320.webp — около 52 КБ вместо исходных 476 КБ; forest-640.webp — около 166 КБ. Hero-480.webp — около 29 КБ вместо 363 КБ у исходника. Реальная экономия зависит от выбранного браузером размера и плотности экрана.

Если заменяете исходные декоративные файлы в static/images, пересоберите варианты командой `python tools/build_web_images.py`, сохраните изменения в Git и обновите статику. Публичные загруженные изображения и новые книги получают варианты автоматически. Кэш производный и может быть восстановлен из оригиналов; учитывайте его место на диске при планировании хранилища.

## Выбор книг и идей

Админка → **«Книги и идеи на главной»** (`/admin/library/homepageitem/`).

1. Добавьте карточку и выберите тип «Книга» или «Идея книги».
2. Для книги выберите опубликованную публичную книгу. Её название, описание и обложка подставятся автоматически. Закрытые/черновые книги не публикуются, а смена доступа автоматически скрывает ранее выбранную карточку.
3. Для идеи укажите название, описание, цвет и собственную обложку либо готовую иллюстрацию. Кнопка идеи ведёт к форме заказа.
4. Включите «Показывать на главной» и задайте порядок. Порядок и видимость можно менять прямо в списке.

Это управляет разделом **«А какая история будет у вас?»**. Карточки выводятся по порядку, при одинаковом числе — по ID. Можно выбрать несколько книг и идей. Если всё выключить, останется приглашение создать книгу. При миграции сохраняется знакомый стартовый набор: первая публичная книга (или идея-приключение), космос и лес. После этого набор меняется только в админке, а не автоматически при публикации новых книг.

## Статистика

Админка → **«Статистика посещений»** → **«Сводка посещений и книг»** (`/admin/library/pagevisit/dashboard/`). Для просмотра требуется `library.view_pagevisit`; обычные читатели и сотрудники без этого права журнал не видят.

В сводке есть периоды 7/30/90 дней, просмотры по дням, оценка посетителей, популярные страницы и книги. По умолчанию распознанные роботы исключены; их можно включить. Подробный журнал показывает время, страницу, книгу и её номер страницы, IP, пользователя, браузер/версию, ОС, тип устройства, User-Agent и домен источника. Доступны фильтры, поиск и выбор даты. Ручное добавление и изменение записей запрещены.

События различаются:

- **Посещение страницы** — успешный GET HTML-страницы сайта.
- **Открытие книги** — загрузка просмотрщика, включая вход по QR и из Android.
- **Переход по страницам книги** — переключение встроенным просмотрщиком без повторной загрузки всего интерфейса.
- **Открытие видеоплеера** — загрузка страницы видео, включая прямую ссылку. Это не счётчик воспроизведений или досмотров.

Статика, картинки, аудио/видео-файлы, опрос состояния видео, HEAD, POST, ошибки и страницы админки не увеличивают статистику. Повторное открытие книги считается новым открытием; открытие не доказывает дочитывание. Раздельные записи переходов показывают активность внутри книги.

Записываются только необходимые для этих отчётов сведения. Query string, тела форм, пароли и секретные адреса `/read/<token>/`, `/watch/<token>/` не сохраняются. Для прямой ссылки в журнал попадает обычный адрес соответствующего просмотрщика. Источник перехода сокращается до домена, без пути, query и данных авторизации.

Оценка посетителей за день использует IP и User-Agent гостя либо аккаунт вошедшего пользователя. Отдельные аналитические cookies и сторонние счётчики не устанавливаются. Общий IP/браузер может объединять людей, смена браузера/IP — разделять одного человека. Браузер и версия определяются из User-Agent и могут быть сокращены или подменены самим клиентом. Это техническая статистика запросов, а не точное измерение уникальных людей.

При удалении аккаунта связанные с ним записи удаляются каскадно. Анонимные записи очищаются по сроку хранения. В `/privacy/` добавлено фактическое описание статистики и текущего срока хранения, без перезаписи редактируемого текста соглашения. Ошибка записи статистики не мешает посетителю открыть страницу.

Источники: [адаптивные изображения](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img#srcset), [Pillow thumbnail](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.thumbnail), [ограничения User-Agent](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/User-Agent).
