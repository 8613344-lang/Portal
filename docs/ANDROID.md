# Android: «Мои книги»

Приложение показывает только персональные и публичные книги платформы. Персональные книги пользователя идут первыми, публичные — ниже; книга, назначенная пользователю и одновременно публичная, не дублируется. Черновики, архив и чужие закрытые книги в каталог не попадают. Без входа видны публичные книги. Учётную запись и персональные доступы создаёт администратор платформы.

Нажатие на книгу открывает общий просмотрщик сразу в режиме «Только страница», с авточтением. Внутри доступны назад/вперёд, пауза, таймер и возврат к книгам. Никаких заказов, сайта-визитки или админки в приложении нет. Android-клиент использует WebView и работает онлайн с вашим сервером; книги не упакованы в APK и не скачиваются для офлайн-чтения.

## Установить и запустить

1. Обновите сервер платформы: `git pull`, затем `docker compose up -d --build`. Клиенту нужны новые маршруты `/app/`, `/app/login/`, `/app/logout/` и обновлённый просмотрщик.
2. Установите APK из `android/releases/PortalBooks-1.0-debug.apk`. При ручной установке Android попросит разрешить установку этому источнику. Это сборка для проверки и личной установки, не публикация Google Play.
3. При первом запуске укажите адрес платформы, например `https://books.example.ru`. Адрес должен содержать только схему, домен и при необходимости порт, без пути `/app/`. Он сохраняется между запусками.
4. Войдите существующим логином платформы, чтобы увидеть персональные книги. Публичные доступны без входа. Пароль не сохраняется в исходниках или настройках приложения; авторизация использует сессионные cookies платформы.

Требуются Android 8.0+ и актуальный Android System WebView. Release-вариант допускает только HTTPS; локальная debug-сборка также допускает HTTP. Ошибки сертификатов не игнорируются. Если указали неверный адрес или сервер недоступен, выберите «Адрес сервера» в сообщении об ошибке и исправьте его.

Для физического устройства используйте адрес, доступный ему в вашей сети. `127.0.0.1` на телефоне означает сам телефон. Для Android-эмулятора можно выполнить `adb reverse tcp:8000 tcp:8000` и использовать `http://127.0.0.1:8000`; сервер должен быть запущен на этом компьютере. Для LAN-адреса также настройте `ALLOWED_HOSTS` и разрешите доступ к порту на сервере.

## Телефон и планшет

Режим определяется автоматически: минимальная ширина устройства от 600 dp — планшет, меньше — телефон. Поворот обновляет компоновку, сохраняя открытую страницу книги.

- Телефон: две колонки обложек в портретной ориентации, три в альбомной. У чередующегося формата картинка и текст располагаются сверху/снизу в портретной ориентации и рядом в альбомной. Обычная страница масштабируется под экран.
- Планшет: три–пять колонок обложек; чередующийся разворот показывает картинку и текст рядом. Обложка и финальный лист остаются отдельными.

Кнопка Android «Назад» из книги возвращает каталог. При сворачивании воспроизведение и таймер приостанавливаются. Персональные файлы продолжают проверяться сервером, а переключение режима не выдаёт доступ к закрытым книгам.

## Собрать из исходников

Откройте папку `android` в Android Studio. Нужны JDK 17+, Android SDK Platform 35 и Build Tools 35.0.0. В репозитории есть Gradle Wrapper 8.11.1, Android Gradle Plugin 8.9.1. Сам клиент не требует сторонних библиотек UI.

```powershell
cd android
# JAVA_HOME — ваша JDK; ANDROID_HOME — ваш Android SDK
.\gradlew.bat assembleDebug
```

Для Linux/macOS: `./gradlew assembleDebug`. Результат: `android/app/build/outputs/apk/debug/app-debug.apk`. Первая сборка скачивает зависимости Gradle/Google Maven. Для удобства кириллицы в Windows включён `android.overridePathCheck`; если ваши инструменты всё равно не работают, используйте каталог с латинским именем.

Если Java под Windows сообщает `Unable to establish loopback connection`, создайте `.gradle/sockets` внутри проекта и задайте перед сборкой:

```powershell
New-Item -ItemType Directory -Force .gradle/sockets
$env:JAVA_TOOL_OPTIONS="-Djdk.net.unixdomain.tmpdir=$(Join-Path (Get-Location) '.gradle/sockets')"
```

В офлайн-окружении, где нет Maven-версии AAPT2, можно использовать AAPT2 установленного SDK через параметр `-Pandroid.aapt2FromMavenOverride=C:/путь/Android/Sdk/build-tools/35.0.0/aapt2.exe`. Это локальная настройка, абсолютные пути SDK в репозиторий не сохраняются.

Для публичного распространения создайте собственный signing key и подписанную release-сборку через Android Studio → Build → Generate Signed App Bundle or APK. Ключ храните вне репозитория; для обновлений нужен тот же ключ. Для Google Play используйте AAB и выполните требования магазина. Debug-APK из репозитория подписан тестовым ключом и содержит разрешение локального HTTP; он предназначен для проверки.

Официальные руководства: [WebView в Android](https://developer.android.com/develop/ui/views/layout/webapps/webview), [совместимость Android Gradle Plugin](https://developer.android.com/build/releases/about-agp), [подпись приложения](https://developer.android.com/studio/publish/app-signing).
