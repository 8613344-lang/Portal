# Android: «Мои книги»

Приложение показывает только персональные и публичные книги платформы. Персональные книги пользователя идут первыми, публичные — ниже; книга, назначенная пользователю и одновременно публичная, не дублируется. Черновики, архив и чужие закрытые книги в каталог не попадают. Без входа видны публичные книги. Учётную запись и персональные доступы создаёт администратор платформы.

Нажатие на книгу открывает общий просмотрщик сразу в режиме «Начать просмотр», с авточтением. Внутри доступны назад/вперёд, пауза, таймер и возврат к книгам. Никаких заказов, сайта-визитки или админки в приложении нет. Android-клиент использует WebView и работает онлайн с вашим сервером; книги не упакованы в APK и не скачиваются для офлайн-чтения.

## Установить и запустить

1. Обновите сервер платформы: `git pull`, затем `docker compose up -d --build`. Клиенту нужны маршруты `/app/`, `/app/login/`, `/app/logout/` и обновлённый просмотрщик.
2. Установите APK из `android/releases/PortalBooks-1.2-debug.apk`. При ручной установке Android попросит разрешить установку этому источнику. Это сборка для проверки и личной установки, не публикация Google Play.
3. Приложение сразу открывает `https://qicko.ru/` в режиме каталога книг. Адрес вводить не нужно; смена сервера в приложении отключена.
4. Войдите по email платформы, чтобы увидеть персональные книги. Публичные доступны без входа. Пароль не сохраняется в исходниках или настройках приложения; авторизация использует сессионные cookies платформы.

Требуются Android 8.0+ и актуальный Android System WebView. Release-вариант допускает только HTTPS; локальная debug-сборка также допускает HTTP. Ошибки сертификатов не игнорируются. Если qicko.ru недоступен, проверьте интернет и доступность сервера. При сетевой ошибке, отказе HTTPS или сбое процесса WebView появляется встроенный экран с повторной загрузкой и переходом в браузер. Приложение не закрывается автоматически. Если системный WebView не запускается, экран объясняет, что нужно обновить Android System WebView или Chrome.

Раздаваемый APK предназначен только для qicko.ru. Для локального тестирования разработчик может отдельно собрать dev-вариант с изменённым URL в MainActivity; пользователь не выбирает сервер.

## Телефон и планшет

Режим определяется автоматически: минимальная ширина устройства от 600 dp — планшет, меньше — телефон. Поворот обновляет компоновку, сохраняя открытую страницу книги.

- Телефон: две колонки обложек в портретной ориентации, три в альбомной. У чередующегося формата картинка и текст располагаются сверху/снизу в портретной ориентации и рядом в альбомной. Обычная страница масштабируется под экран.
- Планшет: три–пять колонок обложек; чередующийся разворот показывает картинку и текст рядом. Обложка и финальный лист остаются отдельными.

Кнопка Android «Назад» из книги возвращает каталог. При сворачивании воспроизведение и таймер приостанавливаются. Персональные файлы продолжают проверяться сервером, а переключение режима не выдаёт доступ к закрытым книгам.

## Собрать из исходников

Откройте папку `android` в Android Studio. Нужны JDK 17+, Android SDK Platform 35 и Build Tools 35.0.0. В репозитории есть Gradle Wrapper 8.11.1, Android Gradle Plugin 8.9.1. Сам клиент не требует сторонних библиотек UI.

```powershell
cd android
# JAVA_HOME — ваша JDK; ANDROID_HOME — ваш Android SDK
.\gradlew.bat assembleDebug
```

Для Linux/macOS: `./gradlew assembleDebug`. Результат: `android/app/build/outputs/apk/debug/app-debug.apk`. Первая сборка скачивает зависимости Gradle/Google Maven. Для удобства кириллицы в Windows включён `android.overridePathCheck`; если ваши инструменты всё равно не работают, используйте каталог с латинским именем.

Если Java под Windows сообщает `Unable to establish loopback connection`, создайте `.gradle/sockets` внутри проекта и задайте перед сборкой:

```powershell
New-Item -ItemType Directory -Force .gradle/sockets
$env:JAVA_TOOL_OPTIONS="-Djdk.net.unixdomain.tmpdir=$(Join-Path (Get-Location) '.gradle/sockets')"
```

В офлайн-окружении, где нет Maven-версии AAPT2, можно использовать AAPT2 установленного SDK через параметр `-Pandroid.aapt2FromMavenOverride=C:/путь/Android/Sdk/build-tools/35.0.0/aapt2.exe`. Это локальная настройка, абсолютные пути SDK в репозиторий не сохраняются.

Для публичного распространения создайте собственный signing key и подписанную release-сборку через Android Studio → Build → Generate Signed App Bundle or APK. Ключ храните вне репозитория; для обновлений нужен тот же ключ. Для Google Play используйте AAB и выполните требования магазина. Debug-APK из репозитория подписан тестовым ключом и содержит разрешение локального HTTP; он предназначен для проверки.

Официальные руководства: [WebView в Android](https://developer.android.com/develop/ui/views/layout/webapps/webview), [совместимость Android Gradle Plugin](https://developer.android.com/build/releases/about-agp), [подпись приложения](https://developer.android.com/studio/publish/app-signing).

Материалы магазина и подробная инструкция: [RuStore](RUSTORE.md). Release использует HTTPS qicko.ru и не запрашивает адрес. Перед публикацией подпишите release вашим ключом; unsigned APK не подходит для загрузки.

## Версия 1.2: проверка запуска

Подписанный debug APK находится в `android/releases/PortalBooks-1.2-debug.apk`, `versionCode=3`. Подпись совпадает с тестовой версией 1.1 из этого репозитория, поэтому её можно обновить без удаления. Если установлен APK, собранный другим ключом на вашем компьютере, Android не позволит заменить его этим файлом: соберите обновление прежним ключом либо удалите старое приложение перед установкой. Книги остаются на сервере; после удаления нужно заново войти. Файл `*-release-unsigned.apk` не устанавливается: его нужно подписать ключом владельца. Контрольные суммы файлов — `android/releases/SHA256SUMS-1.2.txt`.

При сбое приложение показывает причину загрузки вместо автоматического закрытия. Нажмите «Повторить загрузку»; при проблеме системного WebView обновите компонент через магазин устройства. Если падает только конкретный телефон, укажите модель, версию Android и текст ошибки. Для журнала запуска разработчик может выполнить:

```powershell
adb logcat -c
adb shell am force-stop ru.portal.books
adb shell am start -W -n ru.portal.books/.MainActivity
adb logcat -d -s AndroidRuntime:E PortalBooks:V
```

На сайте тот же порядок доступных книг есть в режиме `/shelf/`, ссылка «Книжная полка» в меню. Нажатие открывает просмотр, кнопка возврата и Escape возвращают к полке. Права доступа совпадают с приложением.

Проверка на эмуляторе Android8/API26 без доступного провайдера WebView воспроизвела падение1.1 (`FATAL EXCEPTION`, `MissingWebViewPackageException`). APK1.2 устанавливается и запускается в том же окружении: остаётся активным, показывает встроенный экран восстановления и не падает при повторной загрузке. Это подтверждает исправление данного сценария; точная причина на телефоне пользователя без журнала устройства не установлена. Обычный просмотр и возврат проверены через браузерный интерфейс; физическое Android-устройство не подключалось.
